# Changelog

## Unreleased

### Security
- Fix (P-42, P0): the `text/html` written to the clipboard on copy was not safely escaped. `escapeHtml` ignored `"` / `'` (a link href containing `"` injected attributes such as `onmouseover`), link hrefs were not scheme-checked (`javascript:alert(1)` was emitted as a live link), Dialogue fell back to `<p>${rawText}</p>`, and Image / Video / File `toHtml` concatenated `ref` / `alt` / `name` unescaped.
- New shared module `utils/html.js` (exported from `utils`): `escapeHtml` (`& < > " '`), `escapeAttr`, `sanitizeUrl(url, { kind: 'link' | 'media' })` and `sanitizePasteBlocks()`. `sanitizeUrl` is an allow-list: links accept `http`, `https`, `mailto`, `tel`, relative URLs and `#fragment`; media accept `http`, `https`, `blob:`, the internal `nabu-asset:` scheme, relative URLs and `data:image/*` / `data:video/*`. Everything else (`javascript:`, `vbscript:`, `data:text/html`, `file:`…) is refused, including obfuscated forms (surrounding or embedded whitespace / control characters, mixed case, entity-encoded schemes such as `&#106;avascript:` or `java&Tab;script&colon;`, percent-encoded separators).
- Output: `deltaToHtml` escapes every attribute and renders an unsafe link as its label only (no `<a>`); every block `toHtml` (paragraph, heading, blockquote, callout, code, toggle, list, image, video, file, new `Dialogue.toHtml`) escapes its text / attributes, sanitizes URLs and no longer interpolates unchecked `level` / `variant` values into markup; the generic `handleCopy` fallback for blocks without `toHtml` escapes the text.
- Model: `link:set`, `link:toggle`, `mark:apply` and `TextBehavior.applyMark` refuse an unsafe link href (no-op + `nabu.warn`). `insertFragment()` and `importFragment()` (hence HTML / markdown / `application/x-nabu+json` paste, `importMarkdown()`, `importJSON()`) drop unsafe link marks (the text stays) and empty unsafe `ref` / `src` props.
- Paste: the HTML interpreter drops `javascript:` / `data:` hrefs (text kept as plain text), never reads text from `<object>`, `<embed>`, `<svg>`, `<math>`, `<template>`…, and `<img>` / `<video>` / `<a download>` with an unsafe source no longer become media / file blocks; markdown `![alt](javascript:…)` stays plain text.
- Render: `RichText` never renders an unsafe link mark as a live `<a>` (documents loaded from a snapshot or a remote peer are covered; safe links also get `rel="noopener noreferrer"`); `MediaBlock.displaySrc` only returns a media-safe URL, so Image / Video / File never put `javascript:` in a `src` / `href`.

### Clipboard
- Fix (P-43, P-29): copying a block that has BOTH text and children (list item, toggle) lost content. A boundary hybrid block now serializes its own text slice (clipped to the selection) AND the children inside the selection, recursively clipped; a hybrid that is neither boundary nor fully selected keeps its own text (an item "a" between two selected items was emitted empty). Generic rule in `MegaBlock.serializeForClipboard`: own text first (unless the selection starts inside a child), then the children between the ones holding the selection start and end.
- Fix: structural props now travel with the copy: a to-do item keeps `checked` (it was copied unchecked), a toggle keeps `collapsed` (a collapsed toggle was copied open). New overridable `MegaBlock#clipboardProps` on `ListItem` and `ToggleBlock`.
- Fix (P-45): copying items 2-3 of an ordered list that starts at 3 now yields a list starting at 4 (the first copied item's number) instead of 3. New overridable `MegaBlock#clipboardPropsFrom(firstChildIndex)` (implemented by `List`).
- `text/plain` on copy (P-46): a selection inside ONE text block (paragraph, heading, list item, code…) is now its raw selected text, no markdown syntax (`**`, fences, `# `, `- `); a selection over several blocks is still markdown. `text/html` and `application/x-nabu+json` are unchanged by this rule.
- Paste: a container pasted with its own text (list item, toggle) keeps that text, and a container that needs a parent (a list item pasted at root level) is wrapped like leaf blocks already were.
- Pasting into a list (P-49): "what a list item can hold is absorbed; everything else splits the list". With the caret in a list item, pasted paragraphs (internal fragment, markdown, HTML, multi-line plain text) become ITEMS of that list at the same level (to-do: unchecked), and the items of a pasted list join the current level: they adopt the destination list's type (a numbered list pasted into a bullet list becomes bullets; `checked` is kept only in a to-do list), their own nested sublists are kept as they are. A block an item cannot hold (heading, code, quote, callout, divider, image, video, file, toggle, dialogue…) SPLITS the list at the caret: the items before stay, the block goes right after them, the rest of the list follows below with continued numbering (ordered `start`), reusing `liftItemTo`; the pasted blocks that follow it are inserted as they are (a paragraph stays a paragraph) above the list tail. The first block still merges into the head of the item and the last one (when still inside the list) with its tail; the caret ends after the pasted content; one undo step. Before, the extra paragraphs and lists ended up as invalid children of the list that the normalizer hoisted by accident, and the tail of the item became a paragraph.
- New generic extension point `Block#acceptPaste(blocks, { offset })`: the block holding the caret may take over the insertion of a pasted fragment (return `null` to decline and get the default insertion). `Nabu#insertPasteBlock` and `Nabu#createPasteBlock` are now public (the paste toolbox such a hook builds on). The engine names no block type; the List extension implements the rules (`blocks/list/paste.js`). `liftItemTo` / `retypeItem` take an optional `numbered` flag (a pure placeholder does not consume a number of an ordered list).
- Behaviour change: a whole block pasted as the ONLY block (e.g. markdown `# Title`, an image) at a caret in a list item used to merge its text into the item (a heading) or be silently dropped (an image); it now splits the list as described above.
- Pasting into a toggle (P-50): with the caret in the BODY, everything pasted (paragraphs, lists, headings, code, images, nested toggles…) lands inside the body at the caret, a toggle pasted there is a nested toggle, and an empty body paragraph takes the type of a whole block pasted alone (new overridable `Block#adoptsPastedTypes`, `true` on the toggle; lists keep their structure rules). With the caret in the HEADER, several pasted blocks no longer escape after the toggle: the first text block completes the header at the caret, the others go to the TOP of the body (like Enter in the header), and the header text after the caret follows the last pasted block (merged into it when it is text, otherwise in a new paragraph). Pasting several blocks into a COLLAPSED header expands the toggle (the content would land hidden); a single text block stays an inline merge and keeps it collapsed. One undo step restores header, body and `collapsed`. Implemented through `Block#acceptPaste` (`ToggleBlock`) + the reusable `pasteIntoHeader` sub-thread helper (`blocks/subthread.js`).
- Multi-block paste in the middle of a block (P-50): the text after the caret now continues in a block of the CARET BLOCK'S kind (a heading `Ti|tle` pasted with `[p1, p2]` gives `h(Tip1) ; h(p2tle)`, same for quote, dialogue, callout, with their props), like Enter would. The last pasted block merges with that tail only when it is text (cut at the edge of a partial copy, or a default text block); any other last block (heading, code, container…) is inserted as it is and the tail follows in a new block of the caret block's kind. Without a tail the last pasted block keeps its own type. Before, the tail took the type of the last pasted block (`h(Tip1) ; p(p2tle)`, or a tail swallowed by a code block). A paragraph caret block is unchanged.
- Format versioning (P-52): the `application/x-nabu+json` fragments written on copy / cut carry `version: 1` (`CLIPBOARD_FORMAT_VERSION`). The Nabu paste interpreter reads version 1 and fragments without a version (read as 1); an unknown version is declined with a `nabu.warn` and the paste falls back to the next format of the clipboard (`text/html`, `text/plain`) instead of being mis-parsed. Documented in `docs/design/clipboard-format.md`.
- Unknown block types (P-52): a fragment containing a type the receiving editor does not have registered (copy from a full editor into a minimal one) is degraded instead of being dropped: the block becomes the default text block with its text (and `partial`) kept, its children are kept as normal blocks right after it (recursively degraded; the children of a known container are degraded in place). Before, an unknown container with children disappeared with all its children, and the children of an unknown leaf-like block were created INSIDE a paragraph. New pure `degradeUnknownBlocks` (`utils/extensions.js`), applied by `insertFragment` and `importFragment` (hence `importJSON`), and by the public `insertPasteBlock` / `createPasteBlock`.
- Media across documents (P-51): an image / video / file uploaded in the default mode lives INSIDE the document (`nabu-asset:<id>` ref), so copying it into another Nabu document pasted a ref to an asset that did not exist there (broken media), and the copied `text/html` carried `nabu-asset:` srcs that mean nothing outside Nabu. Now:
  - COPY: the bytes of every `nabu-asset:` media of the fragment are embedded in `application/x-nabu+json` as a top-level `assets: { [id]: { mime, name, size, data: base64 } }` map next to `blocks` (the blocks keep their ref; still `version: 1`, older readers ignore the field). Above `files.maxInlineSize` (total) nothing is embedded and `nabu.warn` says so.
  - PASTE (`insertFragment` / `importFragment`): an asset that already exists in the target is reused (same document, or already pasted once, no duplicate); one carried by the fragment is re-created (without a host hook: stored under the same id, in the paste's own undo step; with `files.onBeforePersist`: sent through `Files#persist`, so the host uploads it, the block appears at once as `pending` with a local preview and gets the host's ref when done; the final swap is a silent commit, not an undo step, so Ctrl+Z / redo treat the paste as ONE step); no bytes: the block is kept with the new `status: 'missing'` and Image / Video / File render a "Missing file" state (`data-nabu-missing`). Never throws; a failing upload ends in `status: 'error'`.
  - `text/html` / `text/plain` on copy never contain `nabu-asset:`: an image / video of at most 1 MB becomes a `data:` URL in the HTML, anything else (larger, non-image file) is a label (alt / file name); markdown gets the alt text / name only. As a consequence the Image / Video / File `toHtml` / `toMarkdown` of a block WITHOUT a source now emit the label (or nothing) instead of `<img src="">` / `<video src="">` / `![]()`.
  - Hosted refs (URLs from `onBeforePersist`, plain http(s)) need nothing and paste unchanged.
  - New `Files#getAsset` / `embedAssets` / `externalize` / `adoptAssets` (`files/files.svelte.js`) and pure helpers in `files/assets.clipboard.js`. `Nabu#commit({ origin })` tags a transaction; an origin starting with `nabu:silent` is excluded from the UndoManager. Documented in `docs/design/clipboard-format.md`.
  - Dev-only `/e2e?hostFiles=1|gated` installs an in-memory `onBeforePersist` for the E2E suite.

### Paste / Files (external content, lot 2)
- Google Docs lists (P-56): the HTML of a Docs list carries its nesting as a LEVEL (`<li aria-level>`; one `<ul>` per level as siblings, or a `<ul>` nested straight in the `<ul>`), not as `<ul>` in `<li>`; it used to paste flat. The levels are now rebuilt as real nested lists: bullet / numbered per level from `list-style-type` (`disc` / `circle` / `square` / `decimal` / `lower-alpha` / `upper-roman`…), `<ol start>` kept, `aria-checked` items make a to-do list; a jump of several levels is clamped.
- Word lists (P-56): consecutive `<p class=MsoListParagraph style="mso-list:l0 level2 lfo1">` become real nested lists (level from `levelN`, one list per `lN lfoN` identity, bullet vs numbered from the ignored marker: `·` `o` `§` `-` / `1.` `a)` `i.`; the first number of a numbered list is kept). The marker is still never text.
- Tables (P-56): with no table block yet, each ROW of a pasted `<table>` is one paragraph, cells separated by a TAB, inline marks (and the style of the cell) kept, nested blocks / lists / tables flattened to text with spaces, `colspan` keeps columns aligned, rows without text dropped, `<caption>` first. Same rows as the `text/plain` TSV of Google Sheets / Excel, which the HTML path (priority 50) already wins over. Declared by the paragraph block as the LOWEST-priority html rule for `table`: a future table block declares its own rule at a higher priority and takes over unchanged.
- Web images (P-56): `<img src>` in external HTML is an image block whose `ref` is the sanitized original URL (nothing is downloaded), `alt` kept. An image inside a paragraph (also inside `<a>` / `<span>` / `<b>`, or a heading) splits it: text before, the image, text after; unsafe (`javascript:`, `data:text/html`) or missing sources (lazy placeholders) are dropped without splitting. An `<img>` without `src` is no longer an empty image block.
- New opt-in `files.importRemote` (default `false`): when `true`, the remote `http(s)` images of a pasted web page are fetched and stored through `Files#persist` (so `onBeforePersist` receives the downloaded `File`), with the optimistic flow (`pending`, the original URL is displayed meanwhile, the swap is a silent commit); a fetch that fails (network, CORS, HTTP error, not a media type) keeps the original URL. No credentials are sent. Documented in the README (Files section).
- Pasting FILES (P-55): `clipboardData.files` (or `items` of kind file) become blocks at the caret, in order, one undo step. New generic extension point `Extension.pasteFileHandlers: [{ priority?, accepts(file, nabu), block(file, nabu) }]` (`PasteFileHandler`): the first handler that accepts a file makes the block (`type` + props other than `ref`); the engine reads the bytes (`Files#stage`) and inserts one fragment through `insertFragment` (hence `Files#adoptAssets`: stored in the document in the default mode, or sent to `onBeforePersist` with a `pending` block and a local preview; the final ref swap stays outside undo). Image (`image/*`), Video (`video/*`) and File (anything else) implement it (`mediaFileHandler`); the engine names no block type. Files win over the text payloads of the same clipboard, except `application/x-nabu+json` (an internal copy wins) and a payload whose interpreter says it outranks files (`PasteInterpreter.outranksFiles`; the HTML one does for a `<table>`: Excel / Sheets also put a picture of the range on the clipboard).
- Fix (P-53): a block without text (image, video, file, divider…) pasted into a NON-empty text block inserted nothing (the inline path merged its empty text). It is now inserted: the caret block is split around it (head, pasted block, tail); at the very start of the text the blank head is not left behind; in an empty block it replaces it as before.
- Engine hooks of the HTML interpreter (generic, used by the rules above): `fromHTML` may return one block, several or none; `static htmlSiblings(el, rule, helpers)` lets a block absorb the following siblings of its element (4th argument of `fromHTML`); an html rule flagged `embed: true` is lifted out of the inline content that contains it; the fragment of an HTML paste is flagged `external`. `ListItem.fromHTML` reads `aria-checked`. Documented in `docs/design/copy-paste.md` (section 13).

### Paste / Markdown (inline, P-48)
- Inline markdown parser rewritten (`paste/markdown-inline.js`, CommonMark / GFM level, used by markdown paste AND `importMarkdown`; `parseMarkdownInline` keeps its name): one scan + CommonMark's delimiter-stack algorithm instead of earliest-match regexes. Links: `[t](url)`, `[t](url "title")` (title ignored), `[t](<url with spaces>)`, parentheses in URLs, marks and nested brackets inside the text; reference links `[t][ref]` / `[t][]` / `[t]` resolved from `[ref]: url "title"` definitions anywhere in the pasted / imported markdown (case-insensitive, first definition wins; definition lines produce no block, fenced code is left alone); autolinks `<https://…>` / `<mailto:…>` / `<a@b.c>` and GFM bare URLs (`https://…`, `www.…`, trailing `?!.,:;*_~` and an unbalanced `)` excluded). Backslash escapes (`\* \_ \[ \# …`), code spans of any backtick length (their content is never parsed), `<u>…</u>`, hard line breaks. Unsafe URLs (`sanitizeUrl`) keep the text and drop the link.
- Images: a line that is only an image is an image block (title ignored, `![alt][ref]` too); an image inside a line splits the paragraph (text before, image block, text after), pasted or imported, through the existing split insertion (P-53). An unsafe image URL keeps the alt text. In headings, list items, quotes… (no block to split) an image is its alt text. A badge `[![alt](img)](url)` becomes the image block (its link is not kept: image blocks have no link).
- Emphasis follows the typing shortcuts: new shared `behaviors/text/markdown-syntax.js` (`delimiterFlags`, `WORD`, escaping helpers) used by the shortcuts, the parser and the exporter: no whitespace just inside the delimiters, `_` never intraword, `*` may be.
- Import joins the lines of a paragraph with a space, except after a hard break (two trailing spaces or a backslash) where the block gets a `\n`. Paste is unchanged: one line = one block.
- `deltaToMarkdown` round-trips: a mark spanning several runs is one delimiter pair (`**a *b* c**`), whitespace at the edge of a span stays outside the delimiters, adjacent runs with the same href share one `[…](href)` (destinations with spaces / unbalanced parentheses use `<…>`), code spans lengthen their fence, markdown-significant characters in text are escaped (`*`, `` ` ``, `[`, `]`, `\`, a non-intraword `_`, `~~`, `<u`…), a block start that would read as another block (`# `, `> `, `- `, `1. `, `-- `, `---`) is escaped, a line break is a hard break (`\` + newline; a callout body keeps the plain newline, its rule re-reads its own lines; new `deltaToMarkdown(delta, { rawBreaks })`).

### Multi-block deletion
- Fix (P-44, P0): cutting (Ctrl+X) a selection that crosses nested-list levels corrupted the document (`ul[]`, Block / DOM out of sync, "Text is deleted" page errors, undo not restoring): `deleteSelectionContent` destroyed the whole root list when both boundaries lived in it. Backspace / typing over the same selection did not corrupt but REORDERED (`x, a>(s1,s2,s3), z` with x@1 -> s2@1 gave `x2, z, s3`).
- One implementation of "delete the selected range across blocks": new `deleteRange(nabu, { startBlock, startOffset, endBlock, endOffset })` in `container.utils.js`, used by cut, Backspace / Delete (any `delete*` input type, word deletions included), typing over a selection, Enter over a selection and paste over a selection (`handleContainerBeforeInput` and `deleteSelectionContent` are now thin wrappers). Generic, no block type involved: head of the start block and tail of the end block are merged at the junction (the end block's children are adopted by it, or promoted after it); what lies strictly inside the range is destroyed; what follows the end point inside the partially-selected blocks of the end spine survives in document order, re-homed after the start block (`requiredParent` honoured); when the start block is an ancestor of the end block (selection from a hybrid's text into its body) the rest of the body stays in place. Survivors are moved out before their former ancestors are destroyed. Type-specific invariants are left to the normalizers. Result: `x@1 -> s2@1` gives `x2, s3, z`.
- Fix: the caret after a multi-block cut landed at the START of the merged block; it now sits at the cut junction (it was set before the commit re-rendered the text). Backspace / typing / Enter over a range place it the same way, after the commit.
- Fix: a word deletion or soft line break over a multi-block selection used to delete the range and then report the input as unhandled; unsupported input types over a range no longer mutate anything.
- Fix: `ListItem#split` sliced the tail with the stale mirrored text length instead of the live one.
- ADR 008 updated: the spine logic now lives in `deleteRange`.

### Paste
- Pasting a whole block (e.g. `# Title`) into an **empty root-level block** now adopts its type. Pasting into existing text, or into a nested block (list item…), never changes the block type.
- Plain-text paste: **one non-blank line = one block** (runs of blank lines are separators). `importMarkdown()` keeps CommonMark semantics (consecutive lines = one paragraph) via the new optional `interpret(raw, nabu, { joinLines })` argument of paste interpreters.
- A paste is always its own undo step; the typing right after it doesn't merge into it.
- New block capability flag `pastesAsPlainText` (default `false`, `true` on Code): pasting inside such a block inserts the clipboard's `text/plain` verbatim (replacing the selection, one undo step) before any paste interpreter runs. No more blocks spilling out of a code block, `# ` / blank lines / `- ` kept as typed.
- External HTML paste (Google Docs, Word, Notion, Wikipedia, GitHub, Sheets, any web page), engine lot (P-56, P-57, P-47). Reproduced by the new corpus `tests/fixtures/html/` (see its README):
  - Inline styles have the last word over tags: `font-weight: normal | 400` (or any weight below 600) cancels the bold of `<b>` / `<strong>`, `font-style: normal` the italic, `text-decoration: none` the underline / strikethrough; `font-weight: bold | 600+`, `font-style: italic | oblique`, `text-decoration: underline | line-through` are still detected. The `style` attribute is parsed directly, so `mso-bidi-font-weight:normal` never counts as `font-weight`. Before, `<b style="font-weight:normal">` and `<strong style="font-weight:400">` were bold (Google Docs' wrapper only escaped it because its block children are flattened; a copy of PART of a line fell through to plain text and lost its marks).
  - Only the marks Nabu knows survive (bold, italic, underline, strikethrough, code, link); colors, fonts, sizes and backgrounds are ignored and a font size never makes a heading. The underline a link gets from its style (Docs, Word) is not a mark.
  - Empty text blocks (`<p></p>`, `<p><br></p>`, `<p>&nbsp;</p>`, empty list items) are dropped; a paste made only of empties inserts nothing; `<pre>` / code and the internal `application/x-nabu+json` path are untouched.
  - Whitespace (P-57): HTML whitespace collapses as in CSS (and is trimmed at line edges; `white-space: pre | pre-wrap | break-spaces` keeps spaces, as Docs' spans use), `<br>` is a line break (a trailing one is ignored). A U+00A0 between two visible characters is KEPT ("10 km", "Bonjour :"); next to another space or at the start / end of a block or line it becomes a regular space (then collapsed). U+202F, U+2007, U+2060, U+00AD, ZWJ and ZWNJ are never touched (emoji family sequences, Persian words).
  - Google redirect links `https://www.google.com/url?q=<target>&sa=D&…` (and `http://`, `google.com`) are unwrapped to their target, then checked by `sanitizeUrl`; a missing, relative, malformed or unsafe target keeps the original link when it is safe.
  - P-47: a container with a `<script>` / `<style>` / `<noscript>` child no longer loses its sibling text (`<div><script>x</script>text</div>` pastes "text"); loose text and inline elements between blocks become paragraphs; scripts and styles never contribute text. A wrapper matching a block rule (`<details>`, a callout) is now that block instead of being flattened. Content of structure without a block yet (table cells, definition lists) is kept as paragraphs rather than lost.
  - Word junk produces nothing: conditional comments (`<![if …]>`, `<!--[if …]-->`), `<o:p>` and other Office namespaces, `mso-*` styles, the `<!--StartFragment-->` markers and the `mso-list:Ignore` bullet markers; `display:none`, `visibility:hidden`, `[hidden]` and `mso-hide` elements are skipped.
  - HTML that only holds inline content (a part of a line copied from Docs or a browser) is read as ONE inline fragment (`partial: 'both'`, one edge space kept) instead of being dropped for the plain-text fallback, so its marks survive.
  - Block-level elements met inside inline content (`<blockquote><p>a</p><p>b</p></blockquote>`) now separate lines instead of gluing their text.
  - Lists and tables keep their exact structure for the next lot; today a table cell is a paragraph and Docs' flat `aria-level` lists are flat.

### Markdown shortcuts
- Block shortcuts (`# `, `- `, `1. `, `[] `, `> `, `! `, `-- `, `--- `) now keep the trigger in the undo history: one Ctrl+Z gives back exactly what was typed (`# `, caret after the space), a second one removes the typing. Implemented once in `nabu.shortcut(block, trigger, transform)` (trigger inserted as a text commit, transform as its own structural step). The code fence (```` ```js ```` + Enter) comes back as the fence line, without the Enter.
- Fix: blocks with `transformsEnabled = false` (Code, Callout, Toggle) are no longer transformed by markdown shortcuts (`# `, `> `, `--- `, `:::`…): the extension `onBeforeInput` hooks are now skipped for typing in such a block (deletion hooks still run), and `nabu.shortcut()` refuses on them. Typing `# comment` in a code block stays plain text.
- Undo/redo restore the caret into the block that exists afterwards: Loro re-creates a block deleted then undone under a new id, so the stored caret now also carries the block's tree path (fixes the lost caret / swallowed key after undoing `- `, `1. `, `[] `).
- Inline shortcuts follow CommonMark flanking rules: no whitespace just inside the delimiters (`2 * 3 * 4`, `* not *` stay literal), `_` / `__` never open or close intraword (`snake_case_name`), `` `a b` `` keeps its spaces. `***both***` typed char by char is bold+italic (the `**…*` rule no longer fires inside a `***` run); `___both___` too.
- Typography: `-- ` becomes an em dash only when the `--` is not preceded by another `-` (`abc --- ` stays).
- `3. ` creates an ordered list that starts at 3: new `start` prop on `List` (`<ol start>`, markdown `3.` `4.`…, markdown / HTML paste, JSON, clipboard). Omitted when 1, ignored for bullet / todo lists; an adjacent list merged into another keeps the first list's start; nested lists start at 1.
- Fix: an ordered list created right under a bullet list was destroyed together with its item by the adjacent-list merge (lists of different types are no longer merged).

### Slash menu
- `/divider` behaves like `--- `: an empty block becomes the divider, otherwise the divider goes after the block (after the whole list inside a list); the caret lands in a new paragraph below. One shared `insertDivider()`.
- The menu is positioned in viewport coordinates (it was off-screen on a scrolled page), flips above the caret when there is no room below, is clamped horizontally and follows the caret on scroll / resize.
- Filtering: titles match by substring, aliases by prefix (`/ul` no longer matches Divider through "rule").

### Undo
- Structural operations (split/Enter, block merge, multi-block deletion, block type transforms incl. markdown shortcuts, list indent/unindent, cut) are their own undo step. Detected centrally at commit time from the pending Loro transaction; plain typing still merges per second.

### Editing
- Fix: block `create()` with `index = 0` (Paragraph, Code, Heading, Blockquote, Divider, Dialogue, Callout, Media, List item) appended the block at the end (`index || undefined`); it is now `index ?? undefined`. Enter in a toggle header puts the new paragraph first in the body.
- The model selection now re-syncs synchronously from the DOM at every input entry point (keydown, beforeinput, compositionstart, copy / cut / paste) via the new idempotent `SvelteSelection.sync()`. `selectionchange` is asynchronous, so a keystroke right after a caret move could act on the previous caret: lost first character after a click, Enter splitting at the old offset, wrong marks range.
- `nabu.exec()` (and `insertFragment()`) now re-sync the model selection from the DOM too, so a programmatic action fired right after a keyboard-only selection change (Shift+Arrow, Home/End, Ctrl+A) acts on the new selection instead of the previous one. `nabu.focus()` returns a promise that resolves once the selection is set (`await nabu.focus(...)` before `exec` / typing); it is asynchronous because it waits for Svelte to render pending blocks.
- Word deletion (Ctrl/Alt+Backspace, Ctrl/Alt+Delete) now uses the model-based rule in every browser: the deleted word takes its surrounding whitespace with it, no orphan or doubled space. Previously Chromium's `getTargetRanges()` bypassed the fix for issue #4.
- Fix (P-34): the caret never rests on a non-text position. Around a Toggle (arrow button, collapsed body), a Divider or an Image the browser parked the native caret on a wrapper / whitespace text node / the editor root, so the next keystroke was swallowed and arrows needed 2-3 presses. `NabuSelection.normalize()` (synchronous, idempotent) now moves any dead endpoint (inert block, element caret, text node outside a text block's own text) to the nearest text position in the direction of travel, skipping void and hidden blocks, in one key press. It runs at selection change, at `keydown` / `keyup` and at `beforeinput` (a keystroke is never swallowed by a dead caret).
- New block capability `hidesChildren` (default `false`; Toggle: collapsed): `findForward` / `findBackward` / `findLastDescendant` and caret navigation never enter a block's hidden children (Backspace after a collapsed toggle no longer merges into its hidden body).
- Fix (P-35): a document ending with a non-text block (divider, image, a container whose end is not a text position) now offers a caret after it. ArrowDown / ArrowRight out of the last text block, and a click in the empty area below the last block, append ONE empty default text block (one undo step) and put the caret in it; nothing is created on load. New `nabu.openTrailingCaret()` / `nabu.lastVisibleBlock`; the default block type comes from the extension flagged `defaultBlock: true` (Paragraph) into `nabu.defaultBlockType`.

### Placeholders
- Placeholders are displayed again (their CSS was disabled). New `placeholders` editor option: `false` to disable, or `{ show: 'focus' | 'empty', text: { [type]: string | false | (block) => string | false } }`. Default `show: 'focus'` (only the empty block holding the caret). Blocks declare their default text with `static placeholder`; color via `--nb-text-placeholder`. `getPlaceholder()` is deprecated.
- `createPersistedEditor()` now forwards all editor init options.

### Lists
- List schema normalizer (`list/normalize.js`, run by the List extension's `onBeforeTransaction`, i.e. inside the transaction/undo step of the operation that broke the structure). Invariants enforced to a fixpoint, with moves only (ids and caret survive): no empty list; no list directly inside a list (unwrapped); only list items inside a list (a foreign block is hoisted out, the list split around it); an item has only lists as children (0..n of them, see P-28 below); adjacent lists of the same type merge.
- Tab / Shift+Tab keep the caret (or range) at the same offset on the moved item (the item's whole text used to end up selected, so the next keystroke replaced it). Indent / unindent now work on tree nodes in `list/indent.js`.
- Tab / Shift+Tab with a selection spanning several items indent / unindent every touched item (document order, relative structure kept, items that cannot move stay, selection restored) as ONE undo step, and the key is always claimed when the selection is in list items, so the focus no longer leaves the editor. Routed by the List extension's `onKeyDown` hook (the keydown of a multi-block selection resolves to the lowest common ancestor, not to an item). `list:indent` / `list:unindent` actions act on the whole selection too.
- **Enter on an EMPTY list item steps back one level**: a nested item is unindented like Shift+Tab (its following siblings become its children), a top-level item leaves the list as a paragraph (list split around it, removed when it was the only item). The exit paragraph used to be inserted inside the parent list item for nested items. The item is retyped in place (same node/id), so its own sub-items are kept as a list below instead of being destroyed.
- **Backspace at offset 0 of a list item steps back one level** (collapsed caret): a nested item is unindented like Shift+Tab; a top-level item alone becomes a paragraph (text, marks, caret kept), the list is split around it, its sub-items stay a list right after it. A second Backspace then merges the paragraph into the previous block as before. Selections, Backspace elsewhere in the item and Delete are unchanged. Implemented in `list/step-back.js`, triggered from the List extension's `onBeforeInput` hook.
- Ordered numbering continues across those splits: the tail list gets `start` = the number its first item had (`1. a 2. b 3. c` with `b` turned into a paragraph reads `1. a`, `b`, `3. c`), taking the original `start` into account.
- **Tab on an item with children moves the whole subtree** one level deeper with it (its children stay its children; they were hoisted to following siblings before). With several selected items, a child selected together with its moved parent is not moved a second time. Shift+Tab keeps the item's children too (followers are appended after them).
- **Changing the type of ONE list item acts on that item only, in place** (slash menu "Numbered list" / "Bulleted list" / "To-do list" / "Text" / "Heading N"…, `block:transform`, `exec('paragraph')`, `exec('heading:1')`, markdown shortcuts typed inside an item). To another list type the item (with its sub-items) goes into a new list between the part before and the part after (`ul[a] ol[b] ul[c]`; adjacent lists of the same type merge, "Numbered list" on a bullet item used to do nothing); the same type is a no-op; entering a to-do list sets `checked: false`, leaving one drops it. To any other block it leaves the list exactly like the top-level Backspace (list split, sub-items stay a list right after it, ordered tail keeps counting through `start`). Converting to another LIST type works at any nesting level, in place (see P-28 below); only a conversion of a NESTED item to a non-list block first unindents it to the top level (what repeated Shift+Tab does: followers become its children). Generic core hook: `Block.retype(type, props)` (mutations only; `transformTo` and `block:transform` use it), overridden by `ListItem`; new `list:convert` action (`{ listType }`) used by the slash menu, which no longer builds lists itself. New `nabu.isolateUndoStep()`.
- **A list item may hold SEVERAL consecutive sublists of DIFFERENT types (P-28)**: `a > [ul[s1], ol[s2], ul[s3]]`, mirroring the root level. The normalizer no longer merges an item's extra sublists into the first one: only ADJACENT sublists of the same type merge (the first keeps its `start`). Converting a nested item to another list type (slash "Numbered list" / "To-do list" / "Bulleted list", `list:convert`) splits its sublist in place inside the same parent item (ordered "after" part keeps counting through `start`; no more promotion to the top level; one undo step), converting it back re-merges. Tab puts the item in the previous sibling's LAST sublist when it has the item's list type, else in a new sublist of that type after the sibling's sublists; Shift+Tab makes the followers children in a sublist of THEIR type after the item's own sublists (the parent's later sublists follow, to keep the document order). Step-back of a top-level item moves ALL its sublists out. Markdown (`- a` / `  - s1` / `  1. s2` / `  - s3`), HTML, JSON and clipboard round-trip them; `ListItem.sublists` (all) replaces the single `sublist` (kept as the first), `sublistsOf(item)` replaces `sublistOf` in `list/indent.js`.
- **Ctrl/Cmd+Enter toggles to-do items**: the item under the caret, or every to-do item of a multi-block selection (any unchecked: check all, else uncheck all). Caret unchanged, one undo step; no-op outside to-do items. The normalizer now also runs when a list's `listType` changes.

### Blocks
- **Behavior change: the markdown syntax of a dialogue line is `-- text` (two hyphens + space), for export AND import / paste, independent of the displayed dash.** The exchange format no longer depends on a visual preference, and `–` / `—` (common list bullets in French text) are never read as dialogue: a line starting with `– ` or `— ` is a plain paragraph. Markdown exported by previous betas with `— text` is therefore NOT recognized as dialogue anymore (deliberate breaking change). New `createDialogueExtension({ dash = '–' })` factory (`DialogueExtension` stays exported as the default instance): `dash` only configures the DISPLAYED marker, through the CSS custom property `--nb-dialogue-dash` (overridable by a host in CSS; default `–`). New `markdownRules` / `fromMarkdown` on `Dialogue` (priority over the list rule: `-- x` is never a list item, `- x` never a dialogue).
- **Toggle sub-thread rules (P-40)**, written as small reusable helpers (`blocks/subthread.js`, tree operations only; a container Callout will reuse them as is):
  - Enter on an EMPTY paragraph that is the LAST child of the body exits the sub-thread: the paragraph moves right after the toggle (caret in it); the toggle may keep an empty body (Enter in the header recreates a first child). Other empty children / other block types keep their usual Enter.
  - **Behavior change:** Backspace at offset 0 of the header turns the toggle into a paragraph with the header text, its body children following it (same parent, in order, nothing lost, one undo step). It no longer merges the header into the previous block, and is no longer a no-op on the first block of the document.
  - **Behavior change:** Enter at the end of a COLLAPSED header creates a paragraph AFTER the toggle (caret in it) and the toggle stays collapsed (it used to expand); Enter in the middle splits the header, the tail goes into that paragraph. An expanded toggle is unchanged (new first body child).
  - Hidden content is never touched: Delete at the end of a collapsed header acts on the next visible block (no-op if none) and the children of a block merged into a collapsed header stay visible after the toggle instead of vanishing into the hidden body; Backspace at offset 0 of the block after a collapsed toggle merges into the header, not into the hidden body.
  - Engine: `Block#ascend` lets a container's handler DECLINE an event (falsy result) so the registered hooks run (the toggle only handles the Enter that exits its body).
- Fix (P-37): a block-type-specific `onSplit` was never run, the generic Paragraph one (registered first) captured the Enter of every block type. `Block#ascend` now runs the hooks registered by the extension that owns the block's type before the generic ones (`nabu.hookOwners`, filled at extension registration; core stays agnostic). Enter in a non-empty dialogue creates a new dialogue line; Enter on an empty dialogue turns it into a paragraph.
- Heading (P-36): Enter in the middle splits into two headings of the same level; at the start of a non-empty heading an empty paragraph is inserted above (heading, level and caret kept); at the end a paragraph is added below (unchanged, also for an empty heading).
- Callout (P-38, interim): Backspace at offset 0 of a non-empty callout is a no-op (nothing merges, variant kept); an empty callout still becomes a paragraph. The callout is planned to become a container.
- Code (P-39): Backspace at offset 0 of a non-empty code block turns it into a paragraph with the same text (language dropped, caret stays at 0); a second Backspace merges normally.
- Divider (P-39): Delete at the end of the block right before a divider deletes the divider (symmetric with Backspace after it); text and caret kept, one undo step. It used to merge the next block across the divider.
- Generic schema rule in `Nabu.commit()`: a block whose class cannot hold children (not a `MegaBlock`) never keeps child nodes. Retyping a node into such a block (`block:transform`, markdown shortcuts, `data.set('type')`) or moving a node under one moves its children to right after it, in order, in the same transaction (nothing is lost; e.g. a list item with a sublist transformed to a paragraph no longer hides the sublist). The tree-subscription no longer throws when a retyped block has no `updateChildren()`.

## alpha.9

### Selection normalizer (breaking fix)

Complete rewrite of `findNearestTextNode` in `selection.svelte.js`. The previous implementation used a sub-walker starting from the beginning of the element, causing the caret to loop back to the start of a zone when trying to exit. The new logic uses `anchorOffset` as the search pivot, correctly determining where in the element the caret landed before deciding whether to look inside or escape past it.

- Arrow keys now correctly exit zones in both directions
- Shift+arrow into an inert element now corrects only the focus, preserving the anchor (non-collapsed selection)
- `data-nabu-ui` elements (zone title input, etc.) bypass normalization entirely

### Zones — nested zones

`zone:insert` and `zone:wrap` now support zones inside zones.

- `zone:insert` detects the nearest zone ancestor and inserts inside it rather than always jumping to root level
- `zone:wrap` (single-block) no longer bails when wrapping inside a zone — creates a nested zone at the correct position
- `zone:wrap` (multi-block) allows wrapping a selection of zones into a new zone
